understanding problem-solving patterns rather than simply storing

## Problem-Solving Approach

For most problems, I try to follow this process:

1. Understand the problem and constraints.
2. Identify the underlying DSA pattern.
3. Work through a small example manually.
4. Develop the algorithm.
5. Implement the solution in C++.
6. Analyze time and space complexity.
7. Add comments explaining important logic.
8. Keep revision notes for concepts worth revisiting.

## Code Documentation

Solutions are generally documented using:

- A detailed explanation at the beginning of the file
- Problem-solving approach
- Important observations
- Time and space complexity
- Short inline comments for important operations

/*
    Problem:
    ...

    Pattern:
